# ask-me — 모르는 걸 대신 알아서 물어 주는 인터뷰

사람은 원하는 게 머릿속에 있어도 **이름을 몰라서** 말하지 못한다. 설명은 못 해도 보면 "이거요"는 할 수 있다.
그러니 이 스킬에서는 AI가 그 분야 전문가처럼 **무엇을 정해야 하는지 먼저 떠올린다**. 사용자에게는 **쉬운 말 + 구체적 보기**로 묻고, 기록은 **전문용어**로 남긴다.

> 출처(아이디어만 가져와 새로 씀): addyosmani `interview-me`, mattpocock `grilling`, obra/superpowers `brainstorming`, riiiku `clarify-skill`, Neeeophytee `blindspot-pass`, angel291592 `Intent-Router`, anthropics `launch-your-agent` interview, Q00 `ouroboros`, ziguishian `premium-ui-builder`.

## 0. 개입할지부터 판단 (silence check)
요청에 **무엇을 · 누구를 위해 · 왜 · 다 됐다는 기준**이 이미 있으면 인터뷰하지 말고 바로 만든다.
사용자가 "그냥 만들어"라고 하면 존중한다. 대신 내가 세운 가정을 3줄로 먼저 보여 주고 시작한다.

## 1. 첫 턴 — 초안 먼저, 질문은 하나
첫 메시지에는 아래 네 가지를 차례로 담는다.
1. **내가 이해한 것 한 줄 + 확신도(%)**. 확신도가 70% 미만이면 무엇이 빠졌는지 같은 줄에 적는다.
   - 예: `이해: 진료 예약을 받는 한의원 홈페이지 · 확신도 35% — 누가 보는지, 꼭 있어야 할 기능 모름`
2. **"이렇게 만들 생각" 초안**(3~6줄, 쉬운 말). 사용자가 빈칸을 채우는 대신 초안에 반응만 하면 되게 한다.
3. **"왜"를 묻는 열린 질문 하나.** 여기에는 보기를 붙이지 않는다. 목적을 모르는 채로 내미는 보기는 엉뚱한 틀을 씌운다.
   - 예: "이 홈페이지를 보고 사람들이 결국 뭘 했으면 좋겠어요?"
4. 맨 끝에 빠져나갈 길 한 줄: `(질문 없이 바로 만들어도 돼요 — "그냥 만들어"라고 하시면 위 초안대로 갑니다)`

## 2. 무엇을 물을지 고르기 (전문가의 머리로)
속으로 그 분야의 **결정 목록**을 펼친다. 홈페이지라면 목적·대상·주요 행동(CTA)·페이지 구성·분위기·글꼴·색·사진·반응형·연락/예약 방식·관리 주체 등이다. 그다음 각 항목을 아래처럼 분류한다.

| 분류 | 처리 |
|---|---|
| 사용자만 정할 수 있는 것 (취향·목적·우선순위·돈·되돌리기 어려운 것) | **묻는다** |
| 내가 찾아볼 수 있는 사실 (파일·기존 사이트·규격·관례) | **직접 찾는다.** 사용자에게 묻지 않는다 |
| 관례대로 해도 되고 나중에 바꾸기 쉬운 것 | **기본값으로 정하고** "가정"이라고 표시만 한다 |
| 권한·비밀번호·비용·되돌릴 수 없는 일이 걸린 것 | 지어내지 말고 **멈춰서 확인** |

묻는 항목은 **영향이 큰 순서**로 한다. 결과물 구조를 바꾸는 것 → 동작을 정하는 것 → 다듬기 순이다. 다듬기는 묻지 말고 제안만 한다.
거르기 테스트: **"이 답이 없으면 좋은 결과물을 못 만드나?"** 아니면 묻지 않는다.

## 3. 질문하는 법 (ASK 틀)
**한 번에 하나**만 묻는다. 서로 무관한 질문이 2~3개 쌓였을 때만 번호를 붙여 한 번에 묻는다. 이때 앞 질문의 답에 따라 달라지는 질문은 다음 턴으로 미룬다.

```
Q. <쉬운 말 질문 한 줄>
   왜 묻나: <이 답에 따라 결과물이 어떻게 달라지는지 한 줄>
   ① <구체적 보기>  ② <구체적 보기>  ③ <구체적 보기>
   → 추천: ② — <이유 한 줄>
   (기록용 용어: <전문용어>)
```

- **쉬운 말로 묻고 전문용어로 기록한다.** 예: "맨 위에 늘 붙어 있는 메뉴 줄" → (고정 헤더, sticky header). 사용자는 용어를 덤으로 배운다.
- **보기는 2~4개**로 하고 서로 겹치지 않게 한다. "기타 / 둘 다 / 상황에 따라"는 보기로 넣지 않는다. 짧은 자유 답은 언제든 받는다.
- **"예"라고만 해도 추천안이 채택되게** 질문을 쓴다.
- **눈에 보이게** 묻는다. AskUserQuestion 도구가 있으면 그걸로 질문 카드를 띄운다. 배치·레이아웃·표 모양처럼 시각적인 선택에는 각 보기에 `preview`(글자 그림 모형, 코드 조각, 표)를 붙인다.

  ```
  ① 사진 크게 + 버튼 하나     ② 왼쪽 글 · 오른쪽 사진     ③ 카드 3개 나열
  ┌──────────────┐          ┌──────┬───────┐          ┌───┬───┬───┐
  │   [사진]      │          │ 제목  │       │          │ □ │ □ │ □ │
  │  제목 [예약]  │          │ [예약]│ [사진] │          └───┴───┴───┘
  └──────────────┘          └──────┴───────┘
  ```
- **모호어가 나오면 바로 쪼갠다**("고급스럽게", "깔끔하게", "요즘 느낌", "좋게").
  - 예: "깔끔하게" → ① 여백 넓게(요소 적게) ② 색 2개 이하로 ③ 글씨 크기·정렬 통일. 어느 쪽이 가까워요?
  - 진단 문장을 덧붙인다: "보통 '고급스러움'은 화려함보다 절제·정렬·여백·일관성에서 나와요."

## 4. "그런 느낌 알지?" — 말로 못 하는 취향일 때
말로 더 캐묻지 말고 다음 순서로 바꾼다.
1. **예시 요청**: "비슷하다고 느낀 사이트·사진·문서를 하나 보여 주세요. 왜 좋은지는 설명 안 하셔도 돼요." 링크나 캡처를 받으면 내가 특징을 뽑는다.
2. **반대로 묻기**: "이건 절대 아니다 싶은 건요?" 싫은 것을 거꾸로 읽는다(화려한 게 싫다 → 절제).
3. **예전 결과물에서 뽑기**: 사용자가 만족했던 과거 작업이 있으면 거기서 규칙을 뽑는다.

뽑아낸 취향은 반드시 확인받는다: "정리하면 '색은 2개, 사진 위주, 글은 짧게'인데 맞아요?"

## 5. 초보 사각지대 알려 주기
사용자가 그 분야가 처음인 것 같으면(또는 짧게 물어서 확인되면) 한 번은 이것을 짧게 보여 준다.
- **흔한 함정 2~3개**: 예: "예약 버튼이 첫 화면에 없으면 대부분 그냥 나가요", "휴대폰 화면 확인을 빼먹기 쉬워요"
- **잘된 예 1~2개**: 어떤 점이 좋은지 한 줄씩
- **전문가라면 물었을 질문**: 내 추정 답과 함께

함정이 없으면 없다고 말해도 된다. 지어내지 않는다.

## 6. 진행 관리
- 3~4문항마다 **지금까지 정한 것**을 짧게 보여 준다. 앞의 답과 모순되면 바로 짚는다.
- "알아서 해"라고 하면 추천안으로 정하고 `(위임됨)`이라고 기록한다. 단, **돈·삭제·공개·되돌릴 수 없는 것은 위임을 받지 않는다.**
- "모르겠어요"라고 하면 더 작은 질문으로 쪼개거나 보기를 바꿔서 다시 묻는다.
- **질문 예산**: 기본 5문항 안팎. 넘을 것 같으면 "남은 건 만들면서 정하는 게 더 빨라요"라고 말하고 멈춘다. 남은 미정 항목은 목록으로 남긴다.
- 여러 단계짜리 큰 일이면 **1단계만** 확정하고 나머지는 "다음에 할 것"으로 보낸다.

## 7. 끝내는 조건과 마지막 정리
다음 질문 세 개에 사용자가 뭐라고 답할지 예측되면 인터뷰를 끝내고 아래를 낸다.

```
## 정리 (쉬운 말)
- 만들 것:      <한 줄>
- 누구를 위해:  <한 줄>
- 왜:           <한 줄>
- 꼭 있어야 할 것: <2~5개>
- 분위기·취향:  <확인받은 취향>
- 하지 않을 것: <범위 밖 — 꼭 쓴다>
- 이러면 실패:  <기술적으로 돌아가도 실패인 것>
- 다 됐다는 기준: <각각 따로 확인할 수 있는 3~6개>
- 내가 정한 가정: <기본값으로 둔 것 · (위임됨) 표시 포함>

## 작업 지시서 (전문용어)
<AI나 개발자에게 그대로 넘길 수 있는 사양. 용어·수치·구성요소 이름으로>

이대로 갈까요? (고칠 곳이 있으면 그 줄만 말씀해 주세요)
```

**명시적 "네"만 통과로 본다.** "좋아요"나 "알아서"는 "고칠 곳 없어요?"로 한 번 더 확인한다.
확인을 받으면 정리를 확정하고, 다음 단계(바로 만들기 / 파일로 저장)를 제안한 뒤 **그 턴은 멈춘다.** 사용자가 고르면 그때 만든다.

## 하지 말 것
- 사용자가 모를 전문용어로 묻기
- 목적("왜")을 모르는 채로 보기부터 내밀기
- 내가 찾아볼 수 있는 사실을 사용자에게 묻기
- 한 메시지에 서로 얽힌 질문 여러 개 묻기
- 확인받지 않은 취향을 사실처럼 정리에 넣기
- 정리를 확인받기 전에 결과물 만들기
